Jullie missie

Bouw in zes sprints een eigen monster-battlegame. De inspiratie komt uit Pokémon: trainers verzamelen monsters, kiezen aanvallen en nemen het tegen elkaar op. Jullie maken wel een eigen spelwereld, eigen namen en eigen spelregels.

Het doel is niet om meteen een perfecte game te bouwen. Het doel is om elke sprint iets kleins werkend op te leveren én steeds een nieuw PHP/OOP-concept te leren.

6 sprints
Eén groeiende game
Werk in teams van 3–4

Scrum: rustig beginnen

Jullie werken in korte sprints. Scrum is geen wedstrijd om de meeste code te typen; het helpt het team om samen werk af te spreken, zichtbaar te maken en te verbeteren.

  • Product Owner: docent, bepaalt samen met de klas wat waardevol is.
  • Scrum Master: één student per sprint, helpt het proces en haalt blokkades naar boven.
  • Developers: alle teamleden bouwen, testen en reviewen.

Wissel de Scrum Master per sprint zodat iedereen kan oefenen.

GitHub is jullie werkplek

  • Alle code staat in de teamrepository.
  • Alle taken zijn GitHub Issues.
  • Het Scrum-bord is GitHub Projects.
  • Werk via branches en Pull Requests.
  • Besluiten en voortgang zijn terug te vinden in GitHub.

Geen werk alleen op je eigen laptop: push regelmatig naar GitHub.

Eenmalige GitHub-inrichting

  1. Maak één repository per team, bijvoorbeeld monster-battle-team-03.
  2. Voeg alle teamleden en de docent toe als collaborator.
  3. Maak een GitHub Project (Board) en koppel de repository.
  4. Maak de kolommen: Product Backlog → Ready → In Progress → Review → Done.
  5. Maak labels: sprint-1 t/m sprint-6, bug, feature, question en blocked.
  6. Maak voor elke user story een GitHub Issue. Zet de sprintlabel, assignee en acceptatiecriteria erbij.
  7. Maak een README.md met teamleden, gamebeschrijving, installatie-instructies en assetbronnen.
Tip voor de docent: maak vooraf één voorbeeldrepository en één GitHub Project aan. Laat studenten tijdens de kick-off in hun eigen team de stappen nadoen.

Praktisch voorstel: één sprint duurt één onderwijsweek. Pas dit aan op het lesrooster. De kick-off is vóór Sprint 1.

Kick-off checklist

  • We kennen de game-opdracht en het einddoel.
  • Iedereen kent de teamleden en eerste Scrum-rollen.
  • De GitHub-repository en GitHub Project bestaan.
  • Iedereen kan clonen, committen, pushen en een Issue vinden.
  • Het team heeft de eerste Product Backlog gevuld.
  • Iedereen weet wat we in Sprint 1 gaan opleveren.
