Jullie missie

De speler krijgt een Trainer met een team monsters. HP wordt gecontroleerd aangepast.

User story
Als speler wil ik een trainer hebben met een team monsters, zodat ik mijn eigen team kan samenstellen.
Sprint 3
Werkende verbetering
in jullie game

Nieuw programmeerconcept

  • public, private en protected
  • Encapsulation: data beschermen
  • Getters en setters waar passend
  • Validatie in methods
  • Een object als property
  • Meerdere objecten bewaren in een array

Wat bouwen jullie?

  1. Maak een klasse Trainer met een naam en team.
  2. Maak HP in Monster private.
  3. Maak takeDamage() en heal() die HP veilig aanpassen.
  4. Voeg monsters toe aan het team via addMonster().
  5. Toon het team op de pagina en laat de speler een actief monster kiezen.

Acceptatiecriteria

De Product Owner (docent) en het team gebruiken deze criteria om te bepalen of het werk echt klaar is.

  • Trainer kan meerdere Monster-objecten bevatten.
  • HP is niet rechtstreeks van buitenaf aanpasbaar.
  • HP kan niet negatief worden en niet boven de maximale HP komen.
  • Een trainer kan een monster aan het team toevoegen.
  • De speler kan één actief monster kiezen.
  • De bestaande battle blijft werken.

GitHub: wat moet zichtbaar zijn?

  • Maak voor elke user story en grotere taak een GitHub Issue.
  • Gebruik het sprintlabel sprint-3 en eventueel feature of bug.
  • Zet Issues op het GitHub Projects-bord: Backlog, Ready, In Progress, Review, Done.
  • Werk op een branch met een herkenbare naam, bijvoorbeeld feature/issue-nummer-korte-naam.
  • Open een Pull Request en vraag minimaal één teamgenoot om review.
  • Verwijs in de PR naar het Issue met Closes #nummer.
  • Verplaats de taak pas naar Done als de acceptatiecriteria zijn gecontroleerd.

Definition of Done

  • De code werkt en is getest.
  • De code staat in een Pull Request.
  • Een teamgenoot heeft de code bekeken.
  • De PR is gemerged naar main.
  • De GitHub Issue is bijgewerkt en gesloten.
  • De werking is te demonstreren.

Scopebewaking

Gebruik voorlopig een vaste lijst monsters in de code. Nog geen login of database. Gebruik setters alleen als ze echt nodig zijn; laat zien waarom een method soms beter is.

Let op: maak eerst de afgesproken functionaliteit af. Extra's zoals geluid, animaties, extra monsters of een winkel zijn pas aan de beurt als de Sprint Goal is gehaald.
